01 — Why it exists

Two datasets.
One connected picture.

Complementary road networks rarely line up. They differ in geometry, completeness, alignment and attribute structure. This toolkit turns that mismatch into a deliberate, repeatable workflow.

≈ 14 m drift

Geometry drift

The same road is digitised differently — offset centrelines, shifted junctions, different vertex density.

duplicate coverage

Duplicate coverage

One source already represents a road well. Adding the second verbatim creates stacked, competing features.

gap in source B

Fragmented completeness

Each dataset covers something the other misses. The goal is a network that keeps the best of both.

Assess first. Integrate second.

The toolkit compares a secondary network against a priority reference using individual priority-road buffers. It measures the largest single-buffer overlap, assigns a legacy Missing_Class, then integrates only the features worth adding.

The priority network stays the reference. You decide how aggressive the integration should be.

03 — Methodology

Three methods.
Three geometry outcomes.

The priority network is always the reference. The method only changes how eligible secondary roads are added.

Method 01

Direct Merge

The fastest path. All priority roads are retained, and secondary features classified missing_1 through missing_4 are appended exactly as they are.

  • No trimming and no snapping
  • Preserves original secondary geometry
  • Writes the legacy three-field schema
Best forPreserving source geometry
Schemacoverage_ratio · Missing_Class · source
Geometry outcomeRetain + append

Priority and secondary features coexist without geometric adjustment.

Method 02

Clip + Snap

Covered portions are removed. The remaining secondary endpoints are pulled to regularly spaced anchors along priority roads, within your snapping distance.

  • Differences eligible roads against the dissolved buffer
  • Builds priority-road anchors at a set interval
  • Saves cumulative class merges for review
Best forRemoving overlap and closing gaps
ControlsJoin gap · densify interval
Geometry outcomeTrim + anchor snap

Trimmed endpoints reconnect to the nearest spaced anchor inside the join gap.

Method 03 plugin default

Targeted Snap

Local context first. Overlap portions are square-buffered to derive nearby priority snap targets, then eligible endpoints try local midpoints, local endpoints and finally a global nearest target.

  • Local midpoint → local endpoint → global fallback
  • Uses centroid adjustment distance
  • missing_1 roads are added without snapping
Best forContext-aware endpoint connections
ControlsSnap distance · centroid adjustment
Geometry outcomeLocal targets + fallback

Nearby overlap context guides the snap before any global nearest-vertex fallback.

Shared foundation. All three methods use the same preparation and classification engine. Priority buffers stay the reference, distances are converted from metres to map units, and work runs through the QGIS task manager.

04 — Coverage logic

Classify before
you integrate.

The classifier uses the remaining-length ratio after the largest overlap with one individual priority-road buffer. Overlaps from separate buffers are never summed.

remaining ratio

(road length − largest single-buffer overlap) ÷ road length

A road that is almost entirely inside a priority buffer is stopped early. A road with no measured overlap is added as missing_1. Everything between follows the documented thresholds — including the intentional gap at exactly 0.25.

05 — Workflow

A guided path from
inputs to verified output.

Preparation, classification, integration and export live in one place, so the workflow is easy to repeat and easy to explain.

  1. 01

    Select source layers

    Choose priority roads, secondary roads and a polygon study-area boundary from your QGIS project.

  2. 02

    Set analysis parameters

    Pick a projected CRS in metres, then review buffers, snapping distance and densification interval.

  3. 03

    Assess coverage

    Reproject, repair and clip the roads, then classify each secondary feature by dominant overlap.

  4. 04

    Choose a method

    Apply Direct Merge, Clip + Snap or Targeted Snap — the plugin's default.

  5. 05

    Run and monitor

    Follow the progress bar and live log. Cancel safely at checkpoints if something looks wrong.

  6. 06

    Review and export

    Write the final network, optionally add it to the project, and retain intermediates for review.

06 — In the background

Heavy geometry work
shouldn't freeze QGIS.

Preparation, overlay, snapping and export run as a QgsTask. You keep working while the toolkit does its job.

  • Recoverable

    Failed geometry is repaired where possible; unsupported outputs are caught before the run.

Before you run it

05 questions
Do I need GeoPandas or Shapely installed?

No. Runtime processing uses PyQGIS, Qt and GDAL only — the components QGIS already ships with. The original Spyder/GeoPandas workflow is what this plugin replaces.

Which CRS should I choose?

A local projected CRS in metres, such as the appropriate UTM zone. Distances are converted if the projected CRS uses non-metre units, but a metric CRS is strongly recommended for snapping and buffer accuracy.

Which output format is best?

GeoPackage is recommended: it supports multiple layers and long field names, and avoids Shapefile's 10-character field limit and single-layer restriction. File Geodatabase output requires a GDAL build with write support, which the plugin checks before processing.

What happens to overlapping secondary roads?

It depends on the method. Direct Merge keeps them untouched. Clip + Snap and Targeted Snap difference eligible roads against the dissolved priority buffer first, then reconnect the remaining endpoints using their respective snapping strategies.

Is it safe to close the dialog mid-run?

Processing runs as a QGIS background task with cancellation at safe checkpoints. Each run keeps its own log file, and reopening the dialog starts from a fresh form.
